# Ревизия релизов и локализаций Blood & Magic

Цель — найти наиболее полную, стабильную и подходящую для реконструкции
сборку оригинальной DOS-игры. Больше файлов **не означает** более полную
функциональность. Поэтому два независимых этапа: статическая ревизия данных
и поведенческая проверка в изолированной DOS-среде.

## Как подготовить материал

Пример структуры на локальном диске:

    D:\BAM-Releases\
        EN-original\
        RU-release\
        DE.zip
        RU-fan-translation\

Каждая папка или ZIP — отдельная **сборка**. Другие архивные форматы,
например ISO, 7z и RAR, сначала надо извлечь в отдельные папки, не
изменяя оригинальные архивы. Вложенные ZIP не открываются.

Запуск из корня репозитория BAM:

    python tools/bam_release_audit.py --from-dir "D:\BAM-Releases" --out ".local\bam-release-audit"

Если сборки находятся далеко друг от друга:

    python tools/bam_release_audit.py --build "RU=D:\OldGames\BAM-RU" --build "EN=E:\Archive\BAM-English.zip" --out ".local\bam-release-audit"

Скрипт не запускает EXE и COM, не распаковывает ZIP, не изменяет исходные
ресурсы и не следует по символьным ссылкам. Файлы хешируются потоково.

## Выходные файлы

| Файл | Содержание |
|---|---|
| summary.md | сводка по сборкам, покрытие групп ресурсов, попарные различия, предупреждения |
| report.json | полный машиночитаемый реестр, SHA-256 и результат сравнения |
| files.csv | каждый найденный файл: путь, размер, SHA-256, расширение, формат ресурса |
| differences.csv | матрица присутствия и различий файлов по всем сборкам |
| functional-checklist.csv | 15 сценариев проверки функций для каждой сборки, по умолчанию not_tested |

Всё создаётся в указанной папке --out (по умолчанию
.local/bam-release-audit). Эта папка исключена из Git. Отчёты содержат
локальные пути: проверьте их на личные сведения перед публикацией.

## Как правильно трактовать результат

### Ресурсная полнота

Покрытие исследуемых сборок по ANI, PAL, SQB, WAV, HMP, FON, TLB, MIF,
EXE и другим расширениям. Имена сравниваются без учёта регистра и
папки установки. Содержимое сопоставляется по SHA-256.

Покрытие вида 410/470 ANI означает: эта сборка содержит 410 разных
имён .ANI из 470 разных имён, найденных **среди предоставленных**
сборок. Это не официальное полное количество. Дубликаты и отличающиеся
файлы при совпадающих именах отмечаются отдельно.

Бинарные различия нельзя автоматически считать ошибкой. Это может
быть исправление, перевод, разная платформа или версия игры.

### Локализация

Различия в SQB, TXT, FON, PAL, меню и исполняемых файлах — кандидаты
на изменения перевода. Проверить кириллицу, шрифты, размеры строк,
перевод миссий и подсказок, сохранения, возможную озвучку.

Не смешивать файлы разных локализаций без проверки внутренних ID
и форматов.

### Функциональная полнота

Отличающийся EXE означает только отличающиеся байты.
Он **не доказывает**, что в одной сборке больше механик или миссий.

functional-checklist.csv содержит 15 обязательных ручных проверок:
запуск и заставка, информация о версии, звуковые настройки,
доступные сценарии, базовые команды, призыв и превращения,
здания, бой, AI, сохранение/загрузка, музыка и эффекты,
локализованные тексты, видео при наличии, условия победы/поражения,
стабильность.

Заполнять result значениями passed / failed / partial / not_applicable
только после запуска. В колонку evidence добавлять путь к скриншоту,
логу или краткому видео. Для старых исполняемых файлов использовать
DOSBox-X либо другую изолированную DOS-среду.

## Критерии выбора

По итогам возможно определить **три разных эталона**:
- эталон графики и ресурсов — максимальное подтверждённое покрытие
  и минимальные проблемы целостности;
- эталон логики — наиболее стабильная и функционально проверенная
  версия EXE;
- эталон перевода — локализация без потерь, с читаемыми строками и
  совместимыми шрифтами.

Они не обязаны совпадать. Сливать их в «суперсборку» до проверки
совместимости нельзя.

## Что передать для второго этапа

Достаточно summary.md и report.json (или ZIP с результатами аудита).
По ним можно составить сравнительную матрицу сборок, выявить
отсутствующие ресурсы, разные EXE и локализационные расхождения,
выбрать базовые версии для дальнейшей проверки.

Исходные EXE и ресурсы необязательно загружать. Для исследования
конкретных несовпадающих форматов или поведения могут понадобиться
дополнительные файлы и подтверждённые результаты DOSBox-проверок.
